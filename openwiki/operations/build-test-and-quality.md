## Responsibility

Keeps builds reproducible and enforces the rules in `AGENTS.md`. A task is not finished until the compiler, the linter, and the tests all report zero issues. The same checks run in CI for the OpenWiki workflow, and the device scripts build and install the app on a connected iPhone.

## Entrypoints

- **Package manifest**: `Package.swift` uses swift-tools-version 5.10 and targets iOS 17 and macOS 14. It declares:
  - the `VocabCraftApp` library target, with `Resources` processed and the entitlements and `PrivacyInfo.xcprivacy` excluded;
  - the `VocabCraftWidgetExtension` target;
  - the `SwiftDataMacros` target;
  - the local `Packages/CraftUIKit` and `Packages/SpeechKit` packages;
  - the `VocabCraftAppTests` test target, which copies the Guided Practice assessment fixture.
- **Xcode**: `VocabCraftApp.xcodeproj` and the workspace are generated by `scripts/generate_workspace.py` and `scripts/generate_xcodeproj.py`.
- **Makefile**: `make deploy-db` runs `scripts/deploy_db.sh` with `DB_FILE`. `make run-device` (or `make build-iphone`) runs `scripts/run_device.sh`.
- **Device scripts**: `scripts/run_device.sh` and `scripts/run-device.sh` find a connected iPhone with `xcrun devicectl`, then build and install the app with `xcodebuild`. `scripts/deploy_db.sh` builds the app and copies the database onto the device.
- **Content generation**: `scripts/generate_shadowing_catalog.py` builds `ShadowingCatalog.sqlite` for the Shadowing feature. See [Shadowing](../features/shadowing.md).
- **Lint configuration**: `.swiftlint.yml` at the root, plus `VocabCraftAppTests/.swiftlint.yml` for the test target.
- **Test support**: `VocabCraftAppTests/Support/XCTestShim.swift` bridges the newer Swift Testing style to the XCTest runner.
- **Performance notes**: `docs/build-optimization.md` records build benchmarks and the optimization settings.
- **CI**: `.github/workflows/openwiki-update.yml` runs on a daily schedule at 08:00 UTC and on manual dispatch. It installs the `openwiki` CLI and runs `openwiki code --update --print`, using an OpenAI key from repository secrets.

## Quality Gate

`AGENTS.md` section 5 defines the gate. Run each step in order and fix every issue before calling a task done:

1. **Localization** — `swift test --filter LocalizationTests`, run for `CraftUIKit`.
2. **Full tests** — `swift test` for the packages and the app test target.
3. **SwiftLint** — `swiftlint`, with zero errors and zero warnings.
4. **Compiler** — Build in Xcode with 0 errors and 0 warnings. Concurrency diagnostics, deprecations, and layout ambiguities count as warnings.

Lint rules enforce the two design rules in `AGENTS.md`. Views must use CraftUIKit tokens and components rather than raw colors and fonts (section 3), and user-facing text must come from localized `AppStrings` keys (section 4). See [Design System](../architecture/design-system.md) and [Localization and Theming](localization-and-theming.md).

## Mechanisms

1. **Build** — `swift build` builds the packages. Xcode builds the app and the widget extension through the workspace.
2. **Tests** — `swift test` runs `CraftUIKitTests`, `SpeechKitTests`, and `VocabCraftAppTests`. The app test target covers domain use cases, the SRS engine, persistence and repositories, the AI and Guided Practice flows, reflex handlers, shadowing, the widget, and localization.
3. **Lint** — `swiftlint` checks the code against `.swiftlint.yml`. The custom rules flag raw colors and hardcoded strings.
4. **Device run** — `make run-device` builds for the connected iPhone and installs it. The script needs a device that `devicectl` can see.
5. **OpenWiki update** — The CI workflow runs `openwiki code --update --print` to refresh the wiki in `openwiki/`.

## Relationships

- **Upstream**: Swift Package Manager resolves the local packages before any build.
- **Downstream**: The quality gate applies to every change. The CI workflow updates `openwiki/`, the repository's documentation, which is what this page describes.

## State and Lifecycle

- SwiftPM writes build artifacts to `.build`. Xcode uses its own DerivedData folder.
- Test runs use in-memory containers, so they do not touch the app group store.

## Invariants

- A task is never complete with a warning, a lint issue, or a failing test.
- Generated Xcode files are regenerated by the scripts, not edited by hand.

## Failure

- Build errors appear as Xcode diagnostics. Lint warnings block the change.
- If the workspace is missing, run `scripts/generate_workspace.py` first.
- If the device script cannot find an iPhone, it stops before it builds.

## Configuration

- Build optimization settings (`SWIFT_OPTIMIZATION_LEVEL`, `DEBUG_INFORMATION_FORMAT`, and `ENABLE_TESTABILITY`) are set per configuration. The rationale is in `docs/build-optimization.md`.
- The OpenWiki workflow uses the `OPENWIKI_PROVIDER`, `OPENWIKI_MODEL_ID`, and `OPENAI_API_KEY` settings from the workflow file. The key comes from repository secrets.

## Extension

- Add a package by adding a target or dependency to `Package.swift`.
- Add a script under `scripts/`, and add a Makefile target if it should be run by name.

## Tests

The test targets are `VocabCraftAppTests`, `Packages/CraftUIKit/Tests/CraftUIKitTests`, and `Packages/SpeechKit/Tests/SpeechKitTests`. Passing all three, plus the lint and compiler checks, is the quality gate itself.
